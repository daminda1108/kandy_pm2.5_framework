## 2.4 Checking that each rung uses exactly its budget

A ladder is only as honest as its rungs. If a rung quietly uses a stream it was not granted, the
gain credited to that rung is inflated. If a rung fails to use a stream it was granted, the rung is
artificially weak and every gain measured above it is inflated instead. We check both directions in
code, so that a violation stops the analysis rather than surfacing in review.

**Using too much.** Every stream is a named object, and every budget is a declared set of streams.
A rung that touches a stream outside its budget raises an error before fitting (`require`). The
budgets are nested by construction, and the nesting is asserted when the code loads.

**Using too little.** A rung that omits a stream its budget admits also raises an error
(`require_covers`), unless the omission is declared at the call site with a stated reason. This
check exists because the first scored version of the ladder failed it: its sensorless rung used
only the reanalysis drivers, one of three admitted streams, and every gain above it was inflated
as a result (the first-station gain fell from 25.6% to 17.9% when corrected) [F.84]. The same
check is applied per city (`require_covers_units`), since a stream can be present for the panel
and absent for one city.

**Streams that are present but empty.** A stream can merge without error and still carry no
values. We check each merged stream's coverage per city (`require_stream_coverage`) and, before
the merge, that the stream's dates overlap each city's record; a satellite stream pulled for the
wrong years once produced a median coverage of zero while the learner returned a plausible result
without warning [gotcha #85].

**The shape of the frame.** Structural checks written as data-frame schemas [pandera 0.33, @Bantilan2020]
require unique city-day keys (a duplicated key would silently multiply rows), physical ranges for
every driver, static features that are non-missing and constant within a city, and at least 100
rows per city. A city absent from any static stream is excluded by name before fitting. These
checks found one city that had been fitted with missing values for all 60 geography features in
three analyses; it is excluded throughout, and the affected results were re-scored [F.113].

An admissibility check cannot see a variable that is inside an admitted stream but never used.
One such case, daily precipitation merged into the frame but absent from the feature list, was
found by inspection and tested as a registered experiment (Section 2.9) [F.112].
